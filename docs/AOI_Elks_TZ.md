# Техническое задание и план работ  
## Проект: **AOI Elks**  
### Автоматизированная оптическая инспекция СМД-монтажа платы Эл242

**Версия:** 1.0  
**Дата:** 02.08.2026  
**Статус:** Утверждено к разработке MVP

---

## 1. Цель проекта

Разработать мобильное Android-приложение для оперативного обнаружения брака СМД-монтажа на плате **Эл242** с помощью камеры обычного смартфона.

Приложение должно работать **полностью оффлайн**, не отправлять фотографии плат в интернет и помогать оператору правильно позиционировать телефон с помощью графических подсказок.

---

## 2. Основные требования

### 2.1. Функциональные требования

| № | Требование | Приоритет |
|---|-----------|---------|
| 1 | Захват изображения платы в реальном времени через камеру телефона | Must |
| 2 | Полностью оффлайн-работа (фото не покидают устройство) | Must |
| 3 | Графические подсказки оператору: поворот, наклон, приближение/удаление | Must |
| 4 | Использование вспышки телефона в режиме фонарика + рекомендации по освещению | Must |
| 5 | Обнаружение брака СМД-монтажа (отсутствие компонента, смещение, tombstoning, грубые мостики, неправильная ориентация) | Must |
| 6 | При обнаружении брака: звуковой сигнал + красный прямоугольник на проблемной области | Must |
| 7 | Поддержка компонентов от 0603 и крупнее + процессор в 48-выводном корпусе | Must |
| 8 | Односторонний монтаж | Must |
| 9 | Возможность загрузки/сохранения эталонного изображения исправной платы | Must |
| 10 | Локальное хранение результатов проверок (дата, время, фото с разметкой) | Should |
| 11 | Режим калибровки (создание эталона) | Must |

### 2.2. Нефункциональные требования

- Работа на Android 8.0+ (API 26+)
- Минимальная камера: 12 Мп
- Время анализа одного кадра: ≤ 2–3 секунды
- Интерфейс на русском языке
- Приложение должно быть простым и понятным для оператора производственной линии

## 3. Описание работы оператора

1. Оператор запускает приложение.
2. При необходимости включает режим калибровки и фотографирует эталонную (исправную) плату.
3. В рабочем режиме наводит камеру на плату.
4. Приложение показывает графические подсказки:
   - Стрелки поворота
   - Индикатор наклона
   - Рамку «приблизь / отдаляй»
   - Подсказку по освещению («Включите фонарик» / «Улучшите освещение»)
5. Когда плата правильно позиционирована — приложение автоматически делает снимок или анализирует кадр.
6. При обнаружении брака:
   - Издаётся звуковой сигнал
   - Проблемная область подсвечивается красным прямоугольником
   - Оператор может скорректировать монтаж и повторить проверку

## 4. Архитектура решения (MVP)

### Технологический стек
- **Язык:** Kotlin
- **UI:** Jetpack Compose
- **Камера:** CameraX
- **Компьютерное зрение:** OpenCV (Android)
- **ML (позже):** TensorFlow Lite
- **Хранение:** Room + локальные файлы
- **Сборка:** GitHub Actions → APK

### Этапы обработки изображения
1. Захват кадра (CameraX)
2. Предобработка (контраст, яркость, удаление бликов)
3. Выравнивание по эталону (feature matching + homography)
4. Разбиение на зоны компонентов / детекция объектов
5. Сравнение с эталоном + простые эвристики / лёгкая модель
6. Отрисовка результатов (красные прямоугольники) + звук

## 6. Ограничения и риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Нестабильное освещение и блики | Высокая | Принудительный фонарик + рекомендации + предобработка |
| Разные углы и расстояния съёмки | Высокая | Графические подсказки + гомография |
| Качество камеры телефона | Средняя | Требование ≥ 12 Мп + хорошая фокусировка |
| Отсутствие размеченного датасета | Высокая | Начинаем с эталонного сравнения, нейросеть — позже |
| Мелкие дефекты (холодная пайка) | Высокая | В MVP детектируем только явный брак |

---

## 7. Критерии готовности MVP

MVP считается готовым, когда:
- Оператор может откалибровать эталон
- Приложение направляет оператора графическими подсказками
- При явном браке (отсутствие компонента 0603+, сильное смещение) появляется красный квадрат + звук
- Всё работает полностью оффлайн
- Собирается APK через GitHub Actions
