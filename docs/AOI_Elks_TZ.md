## Проект: **AOI Elks**  
### Автоматизированная оптическая инспекция СМД-монтажа печатных плат

**Версия:** 1.1  
**Дата:** 02.08.2026  
**Статус:** Утверждено к разработке MVP  
**Изменения v1.1:** Добавлена поддержка нескольких типов плат + каталог на устройстве

---

## 1. Цель проекта

Разработать мобильное Android-приложение для оперативного обнаружения брака СМД-монтажа печатных плат с помощью камеры обычного смартфона.

Приложение должно:
- Работать **полностью оффлайн** (фото не покидают устройство)
- Поддерживать **несколько типов плат** через локальный каталог
- Помогать оператору правильно позиционировать телефон с помощью графических подсказок

Первая плата в каталоге — **Элекс242 ОД2503** (Эл242).

## 2. Основные требования

### 2.1. Функциональные требования

| № | Требование | Приоритет |
|---|-----------|---------|
| 1 | Захват изображения платы в реальном времени через камеру телефона | Must |
| 2 | Полностью оффлайн-работа (фото не покидают устройство) | Must |
| 3 | **Каталог плат** — возможность добавлять, редактировать и выбирать разные типы плат | Must |
| 4 | Для каждой платы в каталоге хранится: название, описание, эталонное фото, ROI-зоны (опционально) | Must |
| 5 | Графические подсказки оператору: поворот, наклон, приближение/удаление | Must |
| 6 | Использование вспышки телефона в режиме фонарика + рекомендации по освещению | Must |
| 7 | Обнаружение брака СМД-монтажа (отсутствие компонента, смещение, tombstoning, грубые мостики, неправильная ориентация) | Must |
| 8 | При обнаружении брака: звуковой сигнал + красный прямоугольник на проблемной области | Must |
| 9 | Поддержка компонентов от 0603 и крупнее | Must |
| 10 | Режим калибровки / добавления новой платы (создание эталона) | Must |
| 11 | Локальное хранение результатов проверок (дата, время, тип платы, фото с разметкой) | Should |
| 12 | Возможность удалить / переименовать плату в каталоге | Should |

### 2.2. Нефункциональные требования

- Работа на Android 8.0+ (API 26+)
- Минимальная камера: 12 Мп
- Время анализа одного кадра: ≤ 2–3 секунды
- Интерфейс на русском языке
- Приложение должно быть простым и понятным для оператора производственной линии
- Данные каталога и эталоны хранятся только локально на устройстве

## 3. Каталог плат (ключевое изменение v1.1)

### 3.1. Структура записи платы в каталоге

```
BoardProfile {
  id: UUID
  name: String              // например "Элекс242 ОД2503"
  description: String?      // краткое описание
  createdAt: DateTime
  updatedAt: DateTime
  referenceImagePath: String // путь к эталонному фото
  thumbnailPath: String?    // уменьшенная копия для списка
  // в будущем:
  roiZones: List<RoiZone>?  // области интереса
  notes: String?
}
```

### 3.2. Экраны, связанные с каталогом

1. **Главный экран** — список плат из каталога + кнопка «Добавить плату»
2. **Карточка платы** — просмотр информации, кнопка «Начать проверку», «Перекалибровать», «Удалить»
3. **Добавление / калибровка платы** — фотографирование эталона + ввод названия

### 3.3. Сценарий работы оператора

1. Открывает приложение → видит каталог плат.
2. Выбирает нужную плату (или добавляет новую).
3. Нажимает «Начать проверку».
4. Следует графическим подсказкам (поворот, наклон, зум, освещение).
5. При обнаружении брака — звук + красный квадрат.
6. Может сохранить результат в локальную историю.

---

## 4. Описание работы с одной платой (проверка)

1. Оператор выбирает плату из каталога.
2. Наводит камеру на плату.
3. Приложение показывает графические подсказки:
   - Стрелки поворота
   - Индикатор наклона
   - Рамку «приблизь / отдаляй»
   - Подсказку по освещению («Включите фонарик» / «Улучшите освещение»)
4. Когда плата правильно позиционирована — анализ кадра.
5. При обнаружении брака:
   - Издаётся звуковой сигнал
   - Проблемная область подсвечивается красным прямоугольником
   - Оператор может скорректировать монтаж и повторить проверку

## 5. Архитектура решения

### Технологический стек
- **Язык:** Kotlin
- **UI:** Jetpack Compose
- **Камера:** CameraX
- **Компьютерное зрение:** OpenCV (Android) — на следующих этапах
- **ML (позже):** TensorFlow Lite
- **Хранение:** Room (каталог плат + история) + файловая система (эталонные фото)
- **Сборка:** GitHub Actions → APK

### Модель данных (Room)

- `BoardEntity` — профиль платы
- `InspectionResultEntity` — результат проверки (ссылка на Board, дата, путь к фото, статус)

### Этапы обработки изображения (на одну плату)
1. Захват кадра (CameraX)
2. Предобработка (контраст, яркость, удаление бликов)
3. Выравнивание по эталону выбранной платы (feature matching + homography)
4. Разбиение на зоны / сравнение
5. Отрисовка результатов (красные прямоугольники) + звук

## 7. Ограничения и риски

| Риск | Вероятность | Митигация |
|------|-------------|-----------|
| Нестабильное освещение и блики | Высокая | Фонарик + рекомендации + предобработка |
| Разные углы и расстояния съёмки | Высокая | Графические подсказки + гомография |
| Качество камеры телефона | Средняя | ≥ 12 Мп + хорошая фокусировка |
| Много разных плат → рост объёма данных | Средняя | Хранение только эталонов + сжатие |
| Мелкие дефекты (холодная пайка) | Высокая | В MVP — только явный брак |

---

## 8. Критерии готовности MVP

MVP считается готовым, когда:
- Можно добавить несколько плат в каталог (с эталонными фото)
- Можно выбрать плату и запустить проверку
- Приложение направляет оператора графическими подсказками
- При явном браке появляется красный квадрат + звук
- Всё работает полностью оффлайн
- Собирается APK через GitHub Actions
